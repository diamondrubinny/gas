# תוכנית — SSO עם Microsoft Entra ID (2.23.0) ✅ בוצע

**בקשה:** מנגנון SSO לחיבור; ספק הזהות: Microsoft Entra ID.
**הנחות עבודה** (לא נענו במפורש): פרוטוקול OpenID Connect; ברירת מחדל: רק משתמשים שכבר קיימים במערכת.

## איך זה עובד
- כפתור "כניסה עם החשבון הארגוני" במסך הכניסה. לחיצה מעבירה ל-Microsoft, ואחרי ההזדהות שם המשתמש חוזר מחובר.
- זרימת Authorization Code עם PKCE, state ו-nonce. הסוד של האפליקציה נשאר בשרת.
- אימות ה-ID token בשרת: חתימה (RS256, מפתחות Microsoft של הדייר), issuer, audience, tenant, תוקף ו-nonce.
- דייר יחיד בלבד (Directory ID). אין תמיכה ב-common / multi-tenant, כדי שחשבון מארגון אחר לא יתקבל.
- זיהוי המשתמש: בכניסה הראשונה לפי שם המשתמש הארגוני (UPN) מול האימייל במערכת, ואז החשבון נקשר למזהה הקבוע של Microsoft (oid). מכאן והלאה ההתאמה לפי oid.
- הגבלת דומיינים (למשל `technion.ac.il`).
- יצירת חשבון אוטומטית: כבויה כברירת מחדל. אם מדליקים: תפקיד ברירת מחדל שאינו מנהל.
- אותם שערים כמו בכניסה רגילה: חשבון פעיל ותפקיד במערכת.
- כניסת SSO לא מבקשת את קוד ה-TOTP של המערכת. האימות הנוסף (MFA) נאכף אצל Microsoft, לפי מדיניות הארגון.

## הגדרה (נדרש צוות IT)
ב-Entra: App registration (Web), Redirect URI שהמערכת מציגה, client secret, והרשאות `openid profile email`.
במערכת ("הגדרות אתר"): Directory (tenant) ID, Application (client) ID, client secret, דומיינים מותרים. כפתור "בדיקת חיבור" מוודא שהדייר קיים.

## מה לא נבנה בשלב הזה
- חיוב SSO וביטול כניסה בסיסמה למנהלים (סכנת נעילה; אפשר להוסיף אחרי שה-SSO עובד בפועל).
- SAML, יציאה מרוכזת (single logout), וסנכרון תפקידים מקבוצות Entra.

## בדיקות
- אינטגרציה: ספק זהות מדומה (מפתח RSA אמיתי, אסימונים חתומים) וכל מסלולי הדחייה.
- דפדפן: כרטיס ההגדרות, הכפתור, כתובת ההפניה ל-Microsoft, והודעות שגיאה.
- **לא ניתן לבדוק כאן:** כניסה מלאה מול Entra אמיתי. זה ייבדק אצלכם אחרי רישום האפליקציה.
