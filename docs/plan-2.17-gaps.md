# תוכנית — סגירת הפערים מול המערכת הישנה

**מצב:** שלבים 1–3 בוצעו (2.17.0, 2.17.1, 2.18.0). תוך כדי שלב 2 נמצא ותוקן באג מהקוד המקורי: טפסים נכשלו ב-"Cookie check failed" אחרי כניסה בלי רענון דף.

מקור: `docs/gap-analysis-old-vs-new.md`. כל שלב: קוד, בדיקות על WordPress 6.4.5 ו-latest, CI ירוק, ורק אז השלב הבא.

## שלב 1 — אימות דו-שלבי מובנה (2.17.0)
- **TOTP (RFC 6238)**, תואם Google Authenticator / Microsoft Authenticator / Authy. בלי ספק חיצוני ובלי SMS.
- **הרשמה** במסך "אבטחה": קוד QR (נוצר מקומית בדפדפן) + מפתח ידני, אישור בקוד, ו-8 קודי גיבוי חד-פעמיים.
- **כניסה:** אחרי סיסמה נכונה נדרש קוד. נאכף בשרת בכל דרכי הכניסה (מסך המערכת, wp-login, XML-RPC). סיסמאות יישום מושבתות למי שהפעיל 2FA.
- **חובה למנהלים** (הגדרה, כבויה כברירת מחדל): מנהל בלי 2FA מופנה למסך ההרשמה, ופעולות ניהול נחסמות בשרת עד שיסיים.
- **אבטחה:** הסוד מוצפן בבסיס הנתונים (AES-256-GCM, מפתח נגזר ממפתחות WordPress). קודי גיבוי נשמרים כ-hash. קוד לא תקף פעמיים. עד 5 ניסיונות ל-15 דקות. ביטול דורש סיסמה. מנהל יכול לאפס 2FA למשתמש אחר. כל אירוע נרשם ביומן הבקרה.
- **שחזור נעילה:** קודי גיבוי, איפוס על ידי מנהל אחר, או `define('GSM_2FA_DISABLE', true)` ב-wp-config.
- **לא בשלב הזה:** Passkeys ו-reCAPTCHA (נשארים המלצה לתוסף).

## שלב 2 — שדות ציוד חסרים (2.17.1, DB v9)
- `purchase_date` (תאריך רכישה) ו-`manual_url` (קישור לחוברת, https בלבד).
- טופס ציוד, כרטיס ציוד, ייבוא Excel, ייצוא, והמשיכה מהאתר הישן (העמודות כבר מזוהות).

## שלב 3 — הודעות מהשטח ומשוב (2.18.0, DB v10)
- **הודעות מהשטח:** כל משתמש מחובר שולח הודעה קצרה; מנהלים רואים כרטיס בדשבורד עם מונה "לא נקראו", סימון כנקרא ומחיקה.
- **משוב ובקשות שיפור:** סוג, עדיפות, כותרת, תיאור; מנהל משנה סטטוס (חדש / בטיפול / בוצע / נדחה).
- שניהם נכללים במדיניות השמירה, בבקשות הפרטיות ובהסרת התוסף.
